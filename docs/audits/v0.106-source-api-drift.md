## Findings

| Surface | v0.106 evidence | Spire Plus impact |
| --- | --- | --- |
| Card pile mutation | `source code/src/Core/Commands/CardPileCmd.cs` exposes `Add(..., AbstractModel? clonedBy = null, bool skipVisuals = false)` and passes `clonedBy` into `Hook.AfterCardChangedPiles`. | Deck/combat adds must pass `clonedBy: null` where no canonical cloned source exists. Tests should reject stale call-shape assumptions. |
| Generated combat cards | `CardPileCmd.AddGeneratedCardToCombat(...)` records combat generation before adding the card, then calls `Hook.AfterCardGeneratedForCombat`. | Morvi/Lotha/Urda generated-card paths must use generated-card APIs only when the card is truly temporary/generated, not for persisted deck rewards. |
| Card reward alternatives | `source code/src/Core/Entities/CardRewardAlternatives/CardRewardAlternative.cs` generates Skip/Reroll, calls `Hook.ModifyCardRewardAlternatives`, and throws if alternatives exceed two. `source code/src/Core/Rewards/CardReward.cs` synchronizes a single card-or-alternative choice index and uses `AfterSelected` to decide reward completion. | Urda Seedbed, Seed Bank, Humus, and Morvi reward choices must share the two-alternative limit and must choose the correct `PostAlternateCardRewardAction` to avoid soft-locks or duplicate rewards. |
| Card reward skip history | `CardReward.OnSkipped()` records unpicked card history and unsubscribes relic reward hooks. | Skip/alternative paths cannot be treated as no-op UI exits; custom alternatives that keep the reward incomplete need explicit reason and live save/load proof. |
| Ancient event start | `source code/src/Core/Models/AncientEventModel.cs` heals the player in `BeforeEventStarted`, applies `WearyTraveler`, and stores generated options through the private `_generatedOptions` list. | Ancient reroll and Vakuu parent-event patches must preserve generated-option history and avoid double-heal behavior on prefinished parent restore. |
| Ancient option generation | `AncientEventModel.GenerateInitialOptionsWrapper()` calls `Hook.ShouldAllowAncient`, then `GenerateInitialOptions()`, replaces null options, and returns a proceed-only option when blocked. | Ancient enable/disable gates should be implemented through hooks and option lists, not by directly mutating event state outside the source lifecycle. |
| Attack intent preview | `source code/src/Core/MonsterMoves/Intents/AttackIntent.cs` computes shown damage through `Hook.ModifyDamage(..., ModifyDamageHookType.All, CardPreviewMode.None, ...)`. `source code/src/Core/Nodes/Combat/NIntent.cs` reads the attack intent label. | Any A19/A20 dedicated ability that changes attack damage must participate in `ModifyDamage` or an equivalent intent-label path so the player sees final damage before being hit. |
| Double boss generation | `source code/src/Core/Runs/RunManager.cs` picks `act.SetSecondBossEncounter(...)` only on the final act when `AscensionLevel.DoubleBoss` is active. | A20 Branded Form must be scoped to the third-act second boss. First-act, second-act, and third-act first boss should remain A19 dedicated abilities only. |
| Parent combat resume | `RunManager.ProceedFromTerminalRewardsScreen()` resumes the previous room when the current room stack is deeper than one and the combat room has `ShouldResumeParentEventAfterCombat`. | Vakuu child combat can source-shape parent return, but no-black-screen victory return remains live-only until game evidence exists. |
| Death prevention | `source code/src/Core/Commands/CreatureCmd.cs` calls `Hook.ShouldDie`, invokes `Hook.AfterPreventingDeath` when prevented, and recurses if the creature is still dead; `force` bypasses the preventer branch. `LizardTail` uses `ShouldDieLate`, and `FairyInABottle` uses `ShouldDie`. | Lotha Death Reprieve must keep per-run/per-combat guards and use forced kill only for the final failure path. Source review does not replace live lethal-path testing. |
| Multiplayer join mismatch | `source code/src/Core/Multiplayer/Game/JoinFlow.cs` checks release version, mod list, and ModelDb hash before join/load. | Spire Plus diagnostics may log these values, but must not paper over version/hash/mod mismatches. |
| Multiplayer ascension cap | `source code/src/Core/Multiplayer/Game/Lobby/StartRunLobby.cs` derives the multiplayer ascension cap from `maxMultiplayerAscensionUnlocked`, persists `PreferredMultiplayerAscension`, and synchronizes through `SyncAscensionChange`. | A11-A20 public selection patches must stay narrow and diagnostic. Co-op correctness still needs two-client proof. |
| Release info | `source code/src/Core/Debug/ReleaseInfoManager.cs` loads `release_info.json` and exposes the game version. | Version docs and compatibility checks should cite the current local install, not stale package notes. |
| Mod config | `EZMicroBalanceCode/MainFile.cs` registers config via `ModConfigRegistry.Register(ModId, new SpirePlusModConfig())`; `EZMicroBalance.csproj` references `Alchyr.Sts2.BaseLib` `3.1.4`, `0Harmony`, and `sts2`. | Preview tools and Spire Plus feature gates stay inside the single Spire Plus mod settings surface. The manifest id remains unchanged. |
